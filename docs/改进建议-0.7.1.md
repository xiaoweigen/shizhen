# 拾帧 0.7.1 · 改进方案与审核

2026-10-04。依据实际使用问题自行提出、审核并执行；本轮优先解决误批量处理、时间轴拖动、在线预览等待和删除记录同步，不增加无关的常驻功能。

## 本轮决策

| 问题 | 方案与审核结论 | 实施 |
| --- | --- | --- |
| 导入时默认勾选导致误处理 | 查看与勾选独立；单个与批量按钮分别说明目标，保留原有勾选 | 已完成 |
| 切换视频继承短选区 | 范围按视频保存，新增默认完整；统一范围需明示确认，超长终点截短，无效批量先整体校验 | 已完成 |
| 时间轴跳动、黄线掉在轴下 | 拖动本地即时反馈，松开后保存；指针共用轨道，范围点击区朝外、播放拖动点在轨道上方，窄选区支持放大 | 已完成 |
| 预览下载和全片转码耗时 | 解析后下载到用户选择位置，优先同清晰度 H.264/AAC，直接本地播放；不自动转码，必要时由用户主动生成兼容副本 | 已完成 |
| 删除后结果与记录不一致 | 成功项清理引用，失败项保留；共享与归档任务一同清理，全部结果删除后移除任务 | 已完成 |
| 删除最后一页出现空页，旧编辑器引用仍在 | 自动回到有效页，删除前保存草稿，完成后刷新编辑器；无关文件和原视频不纳入导出删除 | 已完成 |
| 关闭编辑窗口偶发错误 | 尺寸观察回调保留对应元素，不再读取已置空的引用 | 已完成 |
| 时间数字容易误读 | 保留时分秒与整数毫秒，显示换算并保存偏好；接受视频末尾小于半毫秒的显示舍入 | 已完成 |
| 重复解析产生多份下载 | 完整保存文件直接复用；失效文件要求用户定位或明确下载 | 已完成 |
| 旧备份带来错误范围 | 导入时按各视频时长恢复、校正范围，不依赖当前共用设置 | 已完成 |

不增加“1.5 = 1 分 5 秒”的简写，容易与 1.5 秒混淆；不增加自动全片兼容转换，也不自动重新下载失效素材。旧的“保留下载缓存”选项撤下，保存的视频由用户自行管理。长度剪切继续默认关闭；相关操作保留在下拉菜单，时间轴仍默认展开。

## 后续建议与暂缓理由

| 建议 | 处理 |
| --- | --- |
| 兼容预览缓存管理 | 有用，但应只管理明确登记的副本；本轮已减少自动缓存，暂缓新增管理页 |
| 图片查看跨结果页 | 可减少翻页操作，需完善异步预加载与选图规则；当前查看器范围仍为当前结果页 |
| 独立 Windows 与更多平台样本 | 继续推荐；本机验证不替代新系统安装、第二台设备或真实抖音样本 |
| HDR 长度剪切、字幕与多音轨 | 需要明确保留策略和专用样本，当前仅承诺普通视频的已验证剪切行为 |
| 硬件转码与后台自动转换 | 暂缓；可能改变颜色和耗时，不应恢复用户不希望的自动等待 |

验收结果及具体限制见 [测试报告](测试报告-0.7.1.md)。上述“已完成”表示实现已进入本地版本，不表示已公开发布到远端。
