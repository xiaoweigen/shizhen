## 关键验收

1. 批量导入后没有自动勾选，最新素材自动预览；已有勾选保留。单个处理只操作当前视频，批量只操作已选视频。
2. 切换素材恢复其独立范围，新视频完整范围；明确应用时取消不修改，终点超长会截短，起点无效先整体拒绝，不产生部分修改。重启保留范围和输入模式。
3. 绿色边界拖动时即刻显示并同步实际播放时间，松开才保存；绿色色块移动整段。黄色点定位不改变范围。窄选区的两个绿色手柄能分别点中，指针经过同一轨道，放大和还原有效。
4. 检查常规及紧凑窗口截图。程序最小外框为 1120 × 720，低于此尺寸的测试请求由系统按最小值限制；图片尺寸以测试截图的实际内容区为准。起止输入与各自按钮成组排列，无横向越界。
5. 部分图片删除后备注、索引、配方及共享／归档引用一起清理。模拟一项文件占用失败，其文件和记录保留，其他成功项清理。全部导出结果删除后关闭窗口并移除任务，原视频和同目录无关文件保留。
6. 删除结果最后一页的五张图后自动回到有效页，剩余 60 张仍可查看及编辑；保存草稿不会重新加入已删除引用。
7. Bilibili 样本未配置登录 Cookie，解析后保存至所选文件夹，得到 1080p H.264 视频，原生播放器直接解码、播放和定位。没有自动生成 `cache/playback` 或隐藏的下载副本；临时拼装目录清理。同链接复用文件，无重复任务。
8. 在线抽帧使用已保存文件。暂时移动隔离测试副本后，抽帧和兼容预览均明确拒绝，未偷偷下载；恢复文件后完整性一致。取消文件夹选择不解析、不新增任务。
9. 模拟原生播放失败时未自动转码；主动选择兼容预览后才生成副本，抽帧任务仍引用原保存文件。长视频此可选操作仍可能耗时。
10. 剪切前确认拼接或分别保存，产物加入列表，原视频不改动。托盘隐藏时处理完成，取消关闭保持可见，重启及重复启动行为正常。系统文件夹接口核对通过。

原生文件夹选择、关闭询问和文件管理器调用在自动测试中使用可控返回值或拦截接口；实际窗口隐藏、恢复、队列处理与磁盘文件变化均核对。没有手工逐个点击系统托盘菜单。

## 排查中修复的情况

修复了黄线偏离时间轴、窗口卸载后尺寸观察回调读取空引用、删除最后一页停在空白页、删除后的旧编辑草稿和备份范围恢复。旧 HDR 对照测试要求工具未包含的 PNG 编码器，改为读取原始 RGB 对照，不改变产品输出方式；此前测试定位与虚拟列表断言也按实际界面更新。最终结果来自修正后的完整运行，没有将失败运行包装为通过。

## 安装包、隐私与限制

已生成安装包及免安装目录，打包程序实际运行上述测试。安装包解包后的 711 个文件与测试程序逐一 SHA-256 相同。源码按清单打包，包含全部应用、后台及测试代码，排除个人媒体、Cookie、工作区、原始测试数据和历史私有草稿。检查源码、程序、压缩 Python 代码及安装包的指定私人引用；截图人工查看且无元数据，记录见 [隐私核对](隐私核对-0.7.1.json)。该检查不构成对未知秘密的绝对保证。

没有在干净 Windows 或第二台电脑安装，也没有真实抖音样本；本次 Bilibili 成功不能保证所有链接、清晰度或平台可用。HDR 抽帧通过，不能推断为 HDR 剪切、多音轨和字幕完整保留。查看器目前仍受当前结果页限制。回收站删除不自动退回永久删除，网络盘和特殊存储未测试。

下载编码偏好按清晰度优先再考虑兼容编码，平台不提供兼容格式时保留可选的兼容预览入口。排序依据见 [yt-dlp 官方格式说明](https://github.com/yt-dlp/yt-dlp#sorting-formats)。本报告记录发布前的程序回归。0.7.1 通过独立版本标签和发行页发布，旧版 0.6.1 继续保留；实际远端下载验证另行记录。

交付整理后再次以隔离空工作区启动最终程序，内置处理引擎就绪；原视频内容再次核对一致。
