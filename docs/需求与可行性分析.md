# 需求与可行性分析（当前方案）

整理日期：2026-10-03，版本 0.7.0。本文件整理当前实现，替代早期包含过时选型和实施过程的草稿。

## 产品目标

用户把视频按自定时间间隔保存为独立图片，再对所选图片进行裁剪、排列和故事板编辑。用户控制本地输入及输出位置，处理过程保持可取消、可恢复，并显示实际进度和失败原因。

## 需求与验收规则

| 需求 | 实现与规则 |
| --- | --- |
| 单个与批量输入 | 文件选择/拖入、重复输入检查、损坏与缺失提示；元数据固定位置展示 |
| 项目分类 | 新建、收放、重命名、置顶、拖动与批量移动，重启保留 |
| 按时间抽帧 | 小数间隔、起止范围、起点开关；目标时间命名并记录实际帧时间 |
| 可视化时间轴 | 分:秒.毫秒、可播放预览、拖动同步时间与画面，默认展开且可收起 |
| 长度剪切 | 默认关闭，按视频勾选后启用；保留／移除多段，确认拼接或分别输出，自选文件夹，原文件不变 |
| 文件删除与位置 | 系统文件管理器定位，记录移除与带红字确认的回收站删除分离，不递归删除目录 |
| 窗口与托盘 | 首次关闭询问并记住偏好，后台继续处理，设置可更改，重复启动恢复既有窗口 |
| 保存目录 | 根目录下按视频建子目录，同名与参数冲突保护，核验跳过/另存/覆盖 |
| 分段裁剪 | 默认区域加独立时段，不重叠；空档使用默认区域，按目标时间切换 |
| 拼接 | 所选/全部、单页/批量、预设/自定义行列、排序与替换、末行横向留空 |
| 故事板 | 默认关闭；备注最小高度/字号有效，长文撑高同行，四字段/样式/模板 |
| 查看与编辑 | 可配置快捷键、滚轮缩放、多种平移和退出，输入文本时避免误触 |
| 队列与恢复 | 进度定位、取消/重试、归档/恢复、结果重新导入、备份/重新定位 |
| 在线视频 | 链接解析、元数据预览、单独下载并自选目录，解析器维护和明确诊断 |
| 性能与保护 | 低并发、持续写盘、空间检查、小图缓存、分页/虚拟结果和像素上限 |

## 技术架构

```text
Electron 主进程：文件接口、工作区、队列和独立任务进程
          ↕ 受限的桌面通信接口
React + TypeScript + Ant Design：界面、预览和画面交互
          ↕ 主进程启动独立工作程序
Python：PyAV 解码和时间定位、Pillow 图片与文字、video-mosaic 拼接
       ffprobe 元数据；yt-dlp + FFmpeg 在线下载与合并
```

界面使用 Ant Design 的表单、列表、弹窗和进度控件；裁剪、缩放、选图和故事板画布自行实现。没有引入另一套完整 UI 组件库。抽帧读取源帧时间戳，不依靠平均帧率推算真实画面。上游 video-mosaic 复用拼接和辅助模块，不调用会删除中间截图的命令行流程。

桌面工具能直接处理批量本地文件和任意输出目录，也能运行独立解码/下载程序；浏览器插件更适合网页内操作，纯网页还需处理本地目录授权、格式兼容与跨站限制，当前没有切换架构的必要。

## 可行性与边界

本地导入、抽帧、裁剪、拼接、队列和恢复已在 Windows 的最终免安装版验证。不同编码、旋转、像素比例和可变帧率有独立参考核对。HDR 提供 Hable/Reinhard 转换为 SDR RGB，但目前以生成的 PQ/HLG 样本验证，不能据此承诺所有手机/相机 HDR 的视觉效果。

在线视频依赖平台状态和解析器，Bilibili 已实际完成解析到下载、抽帧和拼接；抖音有效登录内容仍待验证。不同清晰度、分 P 和访问条件按实际链接处理，不提供全站或作者主页批量采集。

低并发与图片持续写出控制处理内存，结果使用小图和虚拟行。视频列表五百条引用工作集仍较高，应优先做列表虚拟显示。干净 Windows 安装、升级、卸载、第二台电脑和 macOS/Linux 打包没有完成验证。

运行架构可行与公开发布准备是两件事。源码、二进制和第三方对应源材料须分别核对；当前公开范围见 [隐私与公开范围](../PRIVACY.md)，技术测试见 [测试报告](测试报告-0.6.0.md)。

0.7.0 预览采用原生可播放视频优先、不兼容时生成 H.264/AAC 缓存；AV1 使用 PyAV 软件解码，独立下载与预览副本分离。长度剪切重新编码，因此会改变画质／体积，时间精度受源帧率约束。兼容预览需要额外存储及准备时间，已提供进度、取消和重试。
