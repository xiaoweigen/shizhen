# 开发说明

Windows x64，Python 3.12，Node.js 24。先按根目录 README 安装依赖，运行 `npm run dev`。`npm run package:win` 生成安装包和完整免安装目录；根目录“启动拾帧”快捷方式指向当前构建。

## 处理层与时间

`backend/core.py` 提供独立的 Processor，处理本地媒体、裁剪、抽帧和拼图；Electron 通过工作进程通信。清单 `frames.target`、`frames.actual` 保持秒，后者来自 `frame.pts * time_base` 减视频流起点，禁止用帧序号除以平均帧率推算。

新增的 `settings.times` 是非空整数毫秒列表，排序去重，优先于 interval、start/end、includeStart 和场景采样。负数、浮点、布尔、非有限数及时长终点／超出时长均报错；实际画面仍选取目标附近的真实解码帧。

## 无界面采样计划

计划JSON最小形状：

```json
{"time_unit":"ms","source_media_id":"sha256:<视频文件哈希>","settings":{"times":[220,339,459]}}
```

```powershell
.\.venv\Scripts\python.exe backend\sample_plan.py --video 'D:\素材\视频.mp4' --plan 'D:\素材\采样计划.json' --output 'D:\截图'
```

入口先核验媒体哈希，再使用现有后端。`--settings` 可指定附加JSON以复用画面裁剪、HDR和拼图设置；times始终以计划为准。该入口属于源码工作流，图形界面仍使用现有间隔与场景选项。

输出清单用实际 `frames.actual` 对齐外部分析。跨剪辑需要明确的时间映射；计划时间不能替代实际时间。时间坐标校准目标≤20ms不代表任意低帧率／VFR视频的目标取帧精度。

## 解码与测试

AV1 实际解码和 PTS 枚举使用 PyAV 软件解码，避免把外部 FFprobe 的硬件解码限制当作没有视频帧。FFprobe仍用于容器信息。原视频只读，视频剪切及导出另存。

保留有回归价值的测试代码，临时素材、缓存、下载验收副本和长日志不入仓库。执行 `npm run test:backend`、`npm run test:desktop` 和 `npm run typecheck`；当前结果见[测试报告](测试报告-0.7.2.md)。第三方二进制重建材料见[对应源材料](二进制发布准备.md)。
